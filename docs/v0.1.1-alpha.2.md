# Excord v0.1.1-alpha.2

This alpha reduces idle background work and the CPU cost of Equicord's patch matching. It retains the bundled catalog and upstream replacement logic. Updates remain manual, and the repository remains private.

## Changes

- Save power while hidden defaults to enabled. Idle hidden windows use Chromium's normal scheduling. Active WebRTC peers and capture tracks request full speed through an event-driven guard. The setting changes immediately.
- The patcher rejects definite misses before allocating replacement state. Its cached string index follows current patches, including additions, edits, and removals. Successful candidates still use the upstream replacement loop.
- Desktop and modification preloads run only in the main Discord frame.
- Repeatable benchmarks record actual logged-out idle CPU, a separate animation workload, first-window timing, working-set totals, and plugin counts. The patcher replay records its corpus hash and cached index. Discord module text is not distributed.

## Observed results

Five alternating pairs per platform, with 30 seconds of settling after the login form appeared, measured hidden animation-workload CPU reductions of 98.7% on Mac and 97.3% on Windows. The patcher replay took 59% less time on Mac and 56% less on Windows. All trials kept the catalog enabled.

Mac first-window timing was about 44 ms slower. Windows startup timings varied across cohorts, and RAM medians were slightly higher in the repeat. These results establish specific CPU savings over the previous Excord build, with no overall startup/RAM lead or quantified ranking against Legcord and Vesktop.

## Scope

See [performance measurements](performance.md) for methods, raw reports, and quantified results. Component timings do not establish whole-app startup gains. Working-set sums can double-count shared pages. The animation workload measures scheduling rather than logged-in scrolling or battery life.

Electron 43.8 does not restore visibility when background throttling is re-enabled while a window is already hidden. Excord defers that transition until the next show. A remotely ended call can therefore keep full-speed scheduling until the window is shown again.

The targets remain Apple silicon macOS 27+ and Windows x64. Mac builds are ad-hoc signed without Developer ID or notarization; Windows builds are unsigned. Login, voice/video calls, capture audio, notifications, tray behavior, and sleep/wake require physical-device checks before inviting friends. The integration test uses a local WebRTC data channel and does not prove microphone or camera behavior.

## Verified build

The kits contain installers from source `f3e4523600a1e9a3b768af4b6569bdeb77f6c705` and [native run 39255717621](https://github.com/extoci/excord/actions/runs/39255717621). Both platform jobs passed strict ts-rust and reference TypeScript checks, 29 unit tests, RPC verification, package assertions, source/ASAR plugin tests, independent normal-shutdown tests, installation/reinstallation with synthetic session persistence, repeated recovery checks, and hidden-window/WebRTC/subframe tests.

Each kit contains the original installer, matching GPL source archive, checksum file, setup guide, and device checklist. ZIP integrity, internal checksums, installer equality, and the source archive's embedded Git revision were checked. The maintainer can forward kits directly without giving friends repository access. Updates remain manual.

The full Equicord catalog remains pinned to `e0e85c8d4f6dc73aac9368cf3f4b2200eac4d4b4`. Benchmark launches load 380 plugin definitions, 1,422 API aliases, and 20 enabled plugins in both builds. This does not establish that every plugin works with a signed-in account.
